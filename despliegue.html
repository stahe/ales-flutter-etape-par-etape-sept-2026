    12. Despliegue

    Durante el desarrollo, la aplicación se ejecuta bajo el control de [flutter run]: en modo “debug”, que es más lento, con recarga en caliente y verificaciones ([assert]) realizadas por [Flutter]. Para desplegarla, se compila en modo “release”: código optimizado, sin herramientas de desarrollo. Se compila una versión por plataforma.

    1
    flutter build web --no-web-resources-cdn

    Dos advertencias, sin consecuencias: la compilación a [WebAssembly] sería posible (véase más abajo); una biblioteca de [Flutter] hace referencia a íconos del estilo [iOS] ([CupertinoIcons]), que la aplicación no utiliza.

    El compilador [dart2js] compiló toda la aplicación ([Dart], [Flutter] y los paquetes) a [JavaScript], en la carpeta [build/web/]:

    • [index.html]: LA página de la aplicación, que carga [flutter_bootstrap.js], luego [main.dart.js] (3.5 MB, aproximadamente 1 MB una vez comprimido por el servidor): NUESTRO código, junto con todo el código de [Flutter] y de los paquetes, optimizado. [Flutter] no genera HTML: la aplicación dibuja cada píxel por sí misma en un lienzo (canvas), con el mismo motor que en el teléfono;
    • [canvaskit/]: este motor de renderizado ([Skia], compilado a [WebAssembly]: [canvaskit.wasm], 7 MB). Sin la opción [--no-web-resources-cdn], se descargaría desde un servidor de [Google]; con ella, se incluye con la aplicación, que ya no depende de ningún sitio externo;
    • [assets/]: los recursos de [pubspec.yaml] (diccionarios, fuentes). Los íconos pasan por “tree-shaking”: solo se conservan en la fuente de íconos los que usa la aplicación;
    • En la primera carga, el navegador descarga unos cuantos megabytes (principalmente el motor de renderizado) y luego los guarda en caché. Esta es la principal debilidad de [Flutter] para la web: se adapta mejor a las aplicaciones (que se abren y se usan durante periodos prolongados) que a los sitios web (que se recorren brevemente).

    La opción [--wasm] compila la aplicación como [WebAssembly] en lugar de [JavaScript]: es más rápida en los navegadores que la admiten (versiones recientes de [Chrome], [Edge] y [Firefox]); los demás navegadores reciben automáticamente la versión [JavaScript].

    1. Colóquela en el servidor. Copie el CONTENIDO de la carpeta [build/web/] en una carpeta llamada [client/] en la raíz del servidor JSON ([rdvmedecins-nestjs-json/client/index.html], [rdvmedecins-nestjs-json/client/main.dart.js]...), luego reinicie el servidor. Muestra:
    1
2
    [Nest] LOG [RdvMedecins] web client served from .../rdvmedecins-nestjs-json/client
[Nest] LOG [RdvMedecins] JSON server started: http://localhost:8080/api

    La aplicación completa ya está disponible en http://localhost:8080. El servidor sirve los archivos del cliente y devuelve [index.html] para cualquier otra dirección fuera de /api: recargar la página /schedule funciona (es el enrutador del cliente el que la muestra). El archivo [src/web/client-spa.ts] del servidor se encarga de esta tarea. La aplicación es servida por el servidor de la API: la dirección relativa de [config.dart] ([''], o [/api/...]) es correcta.

    También puede probar la versión compilada sin el servidor JSON, con cualquier servidor de archivos, pero las solicitudes a /api fallarán.

    12.2. La versión Android

    1. Compile la aplicación, indicando la dirección del servidor:
    1
    flutter build apk --dart-define=SERVER=http://192.168.1.20:8080

    La consola muestra (para un APK compilado sin [--dart-define]):

    1
2
3
4
    Running Gradle task 'assembleRelease'...
Font asset "MaterialIcons-Regular.otf" was tree-shaken, reducing it from 1645184 to 3400 bytes (99.8% reduction). Tree-shaking can be disabled by providing the --no-tree-shake-icons flag when building your app.
Running Gradle task 'assembleRelease'...                          193,4s
√ Built build\app\outputs\flutter-apk\app-release.apk (53.5MB)

    (Se eliminaron algunas advertencias sobre [Gradle] y [Java], que no tuvieron ningún efecto.) La primera compilación tarda mucho: [Gradle] descarga sus propias herramientas y bibliotecas; las compilaciones posteriores son mucho más rápidas.

    El compilador de [Dart] tradujo la aplicación a código máquina para las tres familias de procesadores de los teléfonos [Android] (ARM de 32 bits, ARM de 64 bits, x86 de 64 bits), y la herramienta de compilación de [Android] ([Gradle]) la empaquetó, junto con el motor de [Flutter], en un archivo APK: el formato de instalación de aplicaciones de [Android]. Contiene tres copias de la aplicación y de su motor (una por familia de procesadores), lo que explica su tamaño. [--split-per-abi] generaría tres archivos APK más pequeños, uno por familia de procesadores; un “App Bundle” (véase más abajo) permite que la tienda entregue solo lo que necesita cada teléfono.

    1. Instálela. Con el teléfono conectado a la computadora (cable USB, depuración por USB habilitada):
    1
    flutter install

    También puede copiar el archivo APK en el teléfono y abrirlo: [Android] le pedirá entonces que permita la instalación de aplicaciones “de orígenes desconocidos”.

    1. Para una versión de producción real:
    • la aplicación debe estar firmada con una clave propia del desarrollador: el proyecto generado por [flutter create] firma la versión “release” con la clave de depuración, lo cual es suficiente para pruebas pero no para una tienda. La documentación de [Flutter] (“Build and release an Android app”) describe cómo crear la clave y configurar [Gradle];
    • [Google Play Store] espera un “Android App Bundle” en lugar de un APK: [flutter build appbundle];
    • El nombre y el ícono de la aplicación se configuran en [android/app/src/main/AndroidManifest.xml] ([android:label]) y [android/app/src/main/res/mipmap-*/];
    • El servidor debe configurarse con HTTPS (se transmiten contraseñas), y la línea [android:usesCleartextTraffic="true"] se elimina del manifiesto.

    12.3. El servidor de producción

    En una producción real, no olvide el archivo [.env] en el servidor:

    • un [JWT_SECRET] largo y aleatorio;
    • un [CAPTCHA_TEST] vacío;
    • [COOKIE_SECURE=true] si el sitio se sirve mediante HTTPS (debe ser así). El cliente móvil envía la cookie independientemente de esta opción: es el navegador el que la hace cumplir;
    • [TRUST_PROXY=true] si el servidor está detrás de un proxy ([nginx]...), para que el límite de intentos vea la dirección IP real de los clientes.

    Luego se inicia el servidor compilado: [npm run build], seguido de [npm run start:prod].
