    4. Widgets

    Escribir sus propios widgets es el centro del trabajo con [Flutter]: una pantalla bien escrita se compone de pequeños widgets, cada uno con sus propios parámetros, su [build] y, si es necesario, su estado. Este capítulo muestra cómo se comunican entre sí (parámetros, funciones), cómo se ensamblan (composición), cómo funcionan (ciclo de vida), cómo comparten datos sin pasarlos de uno a otro (datos heredados) y cómo reutilizar comportamientos.

class Doctor {
  final int id;
  final String title;
  final String firstName;
  final String lastName;
  final String specialty;
  final bool available;

  const Doctor({
    required this.id,
    required this.title,
    required this.firstName,
    required this.lastName,
    required this.specialty,
    required this.available,
  });

  // una copia en la que solo cambia la disponibilidad
  Doctor withAvailability(bool d) =>
      Doctor(id: id, title: title, firstName: firstName, lastName: lastName, specialty: specialty, available: d);
}

    // =========================================================================
// lib/ex10_widget_parameters/doctor_card.dart - un widget HIJO
// -------------------------------------------------------------------------
// Recibe sus datos de su padre mediante los PARÁMETROS de su
// constructor, guardados en campos final. Su tipo se verifica en
// tiempo de compilación: DoctorCard(doctor: 42) sería rechazado.
//   - required: el padre DEBE proporcionar este parámetro;
//   - this.compact = false: un parámetro opcional, con su valor por defecto.
//
// Regla de oro: un widget NUNCA MODIFICA sus parámetros (son final).
// Los datos bajan del padre al hijo; para solicitar un
// cambio, el hijo llama a una función que el padre le pasó
// (ver ejemplo 11). Cuando el padre cambia sus datos, RECONSTRUYE
// a sus hijos con nuevos parámetros.
// =========================================================================

import 'package:flutter/material.dart';

import 'doctor.dart';

// el "estilo" de la tarjeta: constantes PRIVADAS de este archivo (el "_").
// Ningún otro widget puede verlas ni verse afectado por ellas
const _initialsColor = Color(0xFF087EA4);
const _initialsStyle = TextStyle(color: Colors.white, fontWeight: FontWeight.bold);

class DoctorCard extends StatelessWidget {
  final Doctor doctor;
  final int rank;
  final bool compact;

  // const: si todos los parámetros son constantes, el widget también lo es
  // (Flutter ni siquiera necesita reconstruirlo)
  const DoctorCard({super.key, required this.doctor, required this.rank, this.compact = false});

  @override
  Widget build(BuildContext context) {
    // un valor calculado a partir de los parámetros
    final initials = '${doctor.firstName[0]}${doctor.lastName[0]}';

    return Card(
      // un borde verde para un médico disponible
      shape: RoundedRectangleBorder(
        borderRadius: BorderRadius.circular(12),
        side: doctor.available ? const BorderSide(color: Colors.green, width: 2) : BorderSide.none,
      ),
      child: Padding(
        padding: const EdgeInsets.all(12),
        child: Row(
          children: [
            CircleAvatar(
              backgroundColor: _initialsColor,
              child: Text(initials, style: _initialsStyle),
            ),
            const SizedBox(width: 12),
            // Expanded: el texto ocupa todo el ancho restante
            Expanded(
              child: Column(
                crossAxisAlignment: CrossAxisAlignment.start,
                children: [
                  Text(
                    '$rank. ${doctor.title} ${doctor.firstName} ${doctor.lastName}',
                    style: Theme.of(context).textTheme.titleMedium,
                  ),
                  if (!compact) Text(doctor.specialty, style: const TextStyle(color: Colors.grey)),
                ],
              ),
            ),
          ],
        ),
      ),
    );
  }
}
    • líneas 23–24: el “estilo” de la tarjeta: constantes privadas de este archivo (el “_”). Ningún otro archivo puede verlas ni verse afectado por ellas. Es el equivalente, en [Flutter], de los “módulos CSS” de [React]: no hay una hoja de estilos global; el estilo de un widget está incorporado en su código;
    • líneas 27–29: los parámetros del widget, almacenados en campos [final];
    • línea 33: el constructor. [required this.doctor]: un parámetro obligatorio, almacenado directamente en el campo; [this.compact = false]: un parámetro opcional, con su valor predeterminado. El constructor es [const]: si todos los argumentos son constantes, la tarjeta también es constante;
    • línea 38: un valor calculado a partir de los parámetros;
    • líneas 42–44: la forma de la tarjeta ([Card]): esquinas redondeadas y un borde verde si el médico está disponible ([BorderSide.none] en caso contrario);
    • líneas 50–52: un disco de color con las iniciales;
    • línea 64: la especialidad solo se muestra en la vista no compacta.

    Regla de oro: un widget nunca modifica sus propios parámetros (son [final]; por cierto, el compilador lo prohíbe). Los datos fluyen del padre al hijo; para solicitar un cambio, el hijo llama a una función que le pasó el padre (ejemplo 11). Cuando el padre cambia sus datos, reconstruye a sus hijos con nuevos parámetros.

// lib/ex10_widget_parameters/main.dart - el widget PADRE
// -------------------------------------------------------------------------
// Importa el widget DoctorCard y lo usa, tantas veces como
// haga falta, como cualquier widget de Flutter: un widget es una pieza
// de interfaz REUTILIZABLE, con sus propios parámetros, su build() y
// su estilo. Escribir sus propios widgets es el corazón del trabajo con
// Flutter: una pantalla bien escrita se compone de pequeños widgets.
// =========================================================================

import 'package:flutter/material.dart';

import 'doctor_card.dart';
import 'doctor.dart';

void main() {
  runApp(
    MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.indigo),
      home: const DoctorsPage(),
    ),
  );
}

class DoctorsPage extends StatefulWidget {
  const DoctorsPage({super.key});

  @override
  State<DoctorsPage> createState() => _DoctorsPageState();
}

class _DoctorsPageState extends State<DoctorsPage> {
  List<Doctor> _doctors = const [
    Doctor(id: 1, title: 'Mme', firstName: 'Marie', lastName: 'PELISSIER', specialty: 'general practitioner', available: true),
    Doctor(id: 2, title: 'Mr', firstName: 'Paul', lastName: 'TATOU', specialty: 'pediatrician', available: false),
    Doctor(id: 3, title: 'Melle', firstName: 'Sophie', lastName: 'DUPONT', specialty: 'general practitioner', available: true),
  ];
  bool _compact = false;

  // el padre cambia SUS datos: Flutter vuelve a llamar a su build(), que
  // reconstruye a los hijos con sus nuevos parámetros
  void _toggleAvailability() {
    setState(() {
      _doctors = [for (final m in _doctors) m.withAvailability(!m.available)];
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Example 10 - the widgets and their parameters')),
      body: ListView(
        padding: const EdgeInsets.all(16),
        children: [
          SwitchListTile(
            contentPadding: EdgeInsets.zero,
            title: const Text('compact display'),
            value: _compact,
            onChanged: (v) => setState(() => _compact = v),
          ),
          Align(
            alignment: Alignment.centerLeft,
            child: OutlinedButton(onPressed: _toggleAvailability, child: const Text('Toggle the availabilities')),
          ),
          const SizedBox(height: 8),
          for (final (i, m) in _doctors.indexed)
            // cada tarjeta recibe SUS parámetros
            DoctorCard(key: ValueKey(m.id), doctor: m, rank: i + 1, compact: _compact),
          const SizedBox(height: 16),
          const Text(
            'The same card, in its compact version, by setting the parameter:',
            style: TextStyle(color: Colors.grey),
          ),
          SizedBox(width: 260, child: DoctorCard(doctor: _doctors[0], rank: 1, compact: true)),
        ],
      ),
    );
  }
}
    • líneas 34–39: el estado del padre: la lista de médicos (una lista constante, que será reemplazada por otra) y la visualización compacta;
    • líneas 43–45: el padre cambia SUS datos por una nueva lista formada por copias de los médicos. [Flutter] llama a su [build], que reconstruye las tarjetas con sus nuevos parámetros;
    • línea 69: una tarjeta por médico, con SUS parámetros. El widget [DoctorCard] se utiliza exactamente como un widget de [Flutter];
    • línea 75: la misma tarjeta, en versión compacta, en un recuadro de 260 puntos de ancho.

    Al inicio, y luego en la vista compacta, la disponibilidad se invierte:

    ¿Un método que crea widgets (como [_line] del ejemplo 02) o un widget real ([DoctorCard])? Casi siempre es preferible el widget real: tiene un nombre, sus parámetros están tipados y documentados, puede reutilizarse en otro lugar, y [Flutter] puede evitar reconstruirlo (si es [const], o si sus parámetros no han cambiado).

    // =========================================================================
// lib/ex11_lifting_state_up/counter.dart
// -------------------------------------------------------------------------
// Un hijo que NOTIFICA a su padre: el padre le pasa FUNCIONES como
// parámetros (por convención, su nombre empieza con "on"), y el hijo
// las llama cuando ocurre algo:
//     Counter(label: 'Coffees', max: 3, onIncrement: ..., onLimit: ...)
// Los tipos de estas funciones tienen nombres predefinidos en Flutter:
//   - ValueChanged<int> : una función que recibe un int y no devuelve nada;
//   - VoidCallback      : una función sin parámetros, que no devuelve nada.
// =========================================================================

import 'package:flutter/material.dart';

class Counter extends StatefulWidget {
  final String label;
  final int max;
  final ValueChanged<int> onIncrement; // con el nuevo valor
  final VoidCallback onLimit; // sin datos

  const Counter({
    super.key,
    required this.label,
    required this.max,
    required this.onIncrement,
    required this.onLimit,
  });

  @override
  State<Counter> createState() => _CounterState();
}

class _CounterState extends State<Counter> {
  // el estado PROPIO de este contador: cada Counter tiene el suyo
  int _value = 0;

  void _plus() {
    // widget: en el objeto State, da acceso a los parámetros del widget
    if (_value >= widget.max) {
      widget.onLimit();
      return;
    }
    setState(() => _value++);
    // se NOTIFICA al padre, y recibe el nuevo valor
    widget.onIncrement(_value);
  }

  @override
  Widget build(BuildContext context) {
    return Row(
      children: [
        SizedBox(width: 110, child: Text(widget.label)),
        OutlinedButton(onPressed: _plus, child: const Text('+1')),
        const SizedBox(width: 12),
        Chip(label: Text('$_value / ${widget.max}')),
      ],
    );
  }
}
    • líneas 18–19: dos parámetros que son funciones, a las que llamará el contador. [ValueChanged<int>] es el tipo de una función que recibe un [int] y no devuelve nada; [VoidCallback] es el tipo de una función sin parámetros. Por convención, sus nombres comienzan con “on”, como [onPressed] o [onChanged] en los widgets de [Flutter];
    • línea 35: el estado PROPIO de este contador: cada [Counter] tiene el suyo;
    • líneas 37–45: dentro del objeto [State], [widget] da acceso a los parámetros del widget: [widget.max], [widget.onLimit]... Si se excede el máximo, el contador notifica a su padre ([widget.onLimit()]); de lo contrario, cambia su estado y luego notifica a su padre transmitiéndole el nuevo valor. A diferencia de [React], el estado se actualiza de inmediato: [_value] ya tiene su nuevo valor cuando se transmite.

    // =========================================================================
// lib/ex11_lifting_state_up/labeled_text_field.dart - un widget CONTROLADO
// -------------------------------------------------------------------------
// Un campo de formulario "casero" (etiqueta + campo + ayuda + contador de
// caracteres) que se usa como un campo controlado:
//     LabeledTextField(value: _name, onChanged: (v) => setState(() => _name = v), ...)
// El valor pertenece al PADRE, que lo pasa (value) y al que
// notifica cada pulsación de tecla (onChanged). El padre es quien decide.
//
// Una dificultad propia de Flutter: un TextField guarda su texto en un
// controlador, que debe sobrevivir a las reconstrucciones. Por tanto, el widget tiene
// un estado (el controlador)... que debe mantener ACTUALIZADO cuando el padre cambia
// el valor (botón "Clear"): ese es el papel de didUpdateWidget.
// =========================================================================

import 'package:flutter/material.dart';

class LabeledTextField extends StatefulWidget {
  final String value;
  final ValueChanged<String> onChanged;
  final String label;
  final int max;
  final String help;

  const LabeledTextField({
    super.key,
    required this.value,
    required this.onChanged,
    required this.label,
    required this.max,
    this.help = '',
  });

  @override
  State<LabeledTextField> createState() => _LabeledTextFieldState();
}

class _LabeledTextFieldState extends State<LabeledTextField> {
  // late: el campo se inicializará más tarde (en initState), antes de cualquier uso
  late final TextEditingController _controller;

  @override
  void initState() {
    super.initState();
    _controller = TextEditingController(text: widget.value);
  }

  // se llama cuando el PADRE reconstruye este widget con nuevos parámetros;
  // oldWidget: el widget anterior, para comparar
  @override
  void didUpdateWidget(LabeledTextField oldWidget) {
    super.didUpdateWidget(oldWidget);
    if (widget.value != _controller.text) {
      _controller.text = widget.value; // el padre cambió el valor por sí mismo
    }
  }

  @override
  void dispose() {
    _controller.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    final full = widget.value.length == widget.max;
    return TextField(
      controller: _controller,
      maxLength: widget.max, // el campo rechaza los caracteres adicionales
      decoration: InputDecoration(
        labelText: widget.label,
        helperText: widget.help,
        // el borde se vuelve rojo cuando el campo está lleno
        errorText: full ? 'Maximum length reached' : null,
      ),
      onChanged: widget.onChanged, // la función del padre, pasada tal cual
    );
  }
}

    Un campo de formulario “personalizado” (etiqueta + campo + información emergente + contador de caracteres) que funciona como un campo controlado: el valor pertenece al padre, que se lo pasa al campo ([value]) y es notificado de cada pulsación de tecla ([onChanged]).

    • Línea 40: [late]: este campo se inicializará más tarde (en [initState]), pero antes de usarse. [Dart] lo verifica en tiempo de ejecución;
    • Líneas 43–45: el controlador comienza con el valor del padre;
    • líneas 51–54: este es el desafío específico de [Flutter]: un [TextField] almacena su texto en un controlador, que debe sobrevivir a las reconstrucciones de la página. Por lo tanto, el widget tiene un estado (el controlador)... que debe mantener al día cuando el padre cambia el valor por sí mismo (botón Borrar). [didUpdateWidget] se llama cada vez que el padre reconstruye este widget con nuevos parámetros; recibe el widget anterior para compararlo. Si el valor del padre difiere del texto del campo, se copia;
    • línea 69: el campo rechaza los caracteres excedentes y muestra un contador (“12/20”);
    • línea 72: una información emergente aparece debajo del campo;
    • línea 74: el borde se vuelve rojo cuando el campo está lleno;
    • línea 76: la función del padre, pasada tal cual a [TextField].

class ParentPage extends StatefulWidget {
  const ParentPage({super.key});

  @override
  State<ParentPage> createState() => _ParentPageState();
}

class _ParentPageState extends State<ParentPage> {
  int _total = 0;
  String _message = '';
  String _firstName = 'Marie';
  String _lastName = 'PELISSIER';

  // la función a la que llama un contador: recibe el valor que el contador le pasa
  void _onIncrement(String label, int value) {
    setState(() {
      _total++;
      _message = '$label is now $value';
    });
  }

  void _clear() {
    setState(() {
      _firstName = '';
      _lastName = '';
    });
  }

  @override
  Widget build(BuildContext context) {
    final titleStyle = Theme.of(context).textTheme.titleSmall;
    return Scaffold(
      appBar: AppBar(title: const Text('Example 11 - the child notifies its parent')),
      body: ListView(
        padding: const EdgeInsets.all(16),
        children: [
          Card(
            child: Padding(
              padding: const EdgeInsets.all(12),
              child: Column(
                crossAxisAlignment: CrossAxisAlignment.start,
                children: [
                  Text('1. Functions called by the children', style: titleStyle),
                  Counter(
                    label: 'Coffees',
                    max: 3,
                    onIncrement: (v) => _onIncrement('Coffees', v),
                    onLimit: () => setState(() => _message = 'No more than 3 coffees!'),
                  ),
                  Counter(
                    label: 'Glasses of water',
                    max: 8,
                    onIncrement: (v) => _onIncrement('Glasses of water', v),
                    onLimit: () => setState(() => _message = 'Enough drinking.'),

import 'package:flutter/material.dart';

// el tipo de una función que construye las celdas de una fila
typedef CellsBuilder<T> = List<Widget> Function(T row, int index);

class SimpleTable<T> extends StatelessWidget {
  final List<T> rows;
  final List<String> columns;
  final CellsBuilder<T> cells;
  final Widget empty; // se muestra cuando no hay ninguna fila

  const SimpleTable({
    super.key,
    required this.rows,
    required this.columns,
    required this.cells,
    this.empty = const Text('No data.'),
  });

  // una celda: un pequeño margen alrededor de su contenido
  static Widget _cell(Widget content) => Padding(padding: const EdgeInsets.all(6), child: content);

  @override
  Widget build(BuildContext context) {
    if (rows.isEmpty) {
      return Column(
        crossAxisAlignment: CrossAxisAlignment.start,
        children: [
          Text(columns.join('   '), style: const TextStyle(fontWeight: FontWeight.bold)),
          const Divider(),
          DefaultTextStyle.merge(
            style: const TextStyle(color: Colors.grey),
            child: empty,
          ),
        ],
      );
    }
    return Table(
      defaultVerticalAlignment: TableCellVerticalAlignment.middle,
      border: TableBorder(horizontalInside: BorderSide(color: Colors.grey.shade300)),
      children: [
        TableRow(
          children: [for (final c in columns) _cell(Text(c, style: const TextStyle(fontWeight: FontWeight.bold)))],
        ),
        for (final (i, row) in rows.indexed)
          // las celdas de ESTA fila, construidas por la función del padre
          TableRow(children: [for (final c in cells(row, i)) _cell(c)]),
      ],
    );
  }
}

// lib/ex13_lifecycle/clock.dart - un widget que se inicia y se detiene
// -------------------------------------------------------------------------
// La vida del objeto State de un StatefulWidget:
//   1. initState()              : acaba de crearse, el widget está a punto de
//                                 aparecer. Lo que debe iniciarse se inicia aquí;
//   2. didChangeDependencies()  : justo después, y luego cada vez que cambia un
//                                 dato heredado que lee (ver ejemplo 14);
//   3. build()                  : tantas veces como haga falta;
//   4. didUpdateWidget(old)     : el padre lo reconstruyó con nuevos
//                                 parámetros;
//   5. dispose()                : el widget desaparece definitivamente. Lo que
//                                 se inició se DETIENE aquí.
// Un reloj lanza un temporizador (Timer.periodic) cuando aparece...
// y debe detenerlo imperativamente cuando desaparece: de lo contrario, el
// temporizador seguiría ejecutándose inútilmente, y llamaría a setState()
// sobre un objeto muerto (un error).
// =========================================================================

import 'dart:async';

import 'package:flutter/material.dart';

String currentTime() => DateTime.now().toString().substring(11, 19); // "12:05:09"

class Clock extends StatefulWidget {
  final ValueChanged<String> onLog;
  final Color color;

  const Clock({super.key, required this.onLog, this.color = Colors.indigo});

  @override
  State<Clock> createState() => _ClockState();
}

class _ClockState extends State<Clock> {
  String _time = currentTime();
  // late: se inicializa en initState
  late final Timer _timer;

  // notificar al padre... DESPUÉS de la construcción de la pantalla actual: no
  // modificamos el estado de un widget (el padre) mientras se está construyendo
  void _log(String message) {
    WidgetsBinding.instance.addPostFrameCallback((_) => widget.onLog(message));
  }

  @override
  void initState() {
    super.initState(); // siempre primero
    _log('Clock: initState - starting the timer');
    _timer = Timer.periodic(const Duration(seconds: 1), (_) {
      setState(() => _time = currentTime());
    });
  }

  @override
  void didUpdateWidget(Clock oldWidget) {
    super.didUpdateWidget(oldWidget);
    if (oldWidget.color != widget.color) {
      _log('Clock: didUpdateWidget - new color');
    }
  }

  @override
  void dispose() {
    _timer.cancel(); // la LIMPIEZA
    _log('Clock: dispose - timer stopped');
    super.dispose(); // siempre último
  }

  @override
  Widget build(BuildContext context) {
    return Text(
      _time,
      style: TextStyle(fontSize: 40, fontFamily: 'RobotoMono', color: widget.color),
    );
  }
}

    Método
    ¿Cuándo?
    initState()
    El objeto acaba de crearse; el widget va a aparecer. Aquí se inicia todo lo que deba iniciarse (temporizador, suscripción, etc.)
    didChangeDependencies()
    Inmediatamente después de initState, y luego cada vez que cambia algún dato heredado que lee (véase el ejemplo 14)
    build()
    tantas veces como sea necesario
    didUpdateWidget(old)
    el padre lo ha reconstruido con nuevos parámetros
    dispose()
    el widget desaparece definitivamente. Todo lo que se inició allí se detiene
    • líneas 37–39: el estado: la hora mostrada y un temporizador ([Timer], de la biblioteca [dart:async]);
    • líneas 43–44: el reloj notifica a su padre cada etapa de su ciclo de vida. Pero lo hace durante [initState] o [dispose], es decir, mientras [Flutter] construye la pantalla: el padre no puede modificar su estado en ese momento ([setState] provocaría un error). [addPostFrameCallback] difiere la llamada hasta después de que termine de dibujarse el cuadro actual;
    • líneas 48–52: [super.initState()] primero, siempre. Luego se inicia un temporizador periódico: su función se llama cada segundo y actualiza la hora;
    • líneas 57–60: el padre ha redibujado el reloj con un color diferente: se toma nota de ello;

// ¿Cómo compartir datos y funciones entre widgets distantes,

//   1. un widget PROVEEDOR, colocado en lo alto del árbol, lleva los datos;

//      con context.dependOnInheritedWidgetOfExactType<Provider>();

// Es el mecanismo que usa el propio Flutter: Theme.of(context),
// MediaQuery.of(context), Navigator.of(context)... son lecturas de
// datos heredados.
//
// InheritedNotifier es una variante lista para usar: el dato es un objeto
// que NOTIFICA sus cambios (un ChangeNotifier, que llama a
// notifyListeners()), y el proveedor reconstruye entonces a sus lectores.
// La convención: un método estático of(context) para leer el dato.
// =========================================================================

import 'package:flutter/material.dart';

// el dato: un ChangeNotifier. notifyListeners() notifica a sus suscriptores
class Log extends ChangeNotifier {
  final List<String> lines = [];

  void trace(String message) {
    lines.insert(0, '${DateTime.now().toString().substring(11, 19)} $message');
    if (lines.length > 6) lines.removeLast();
    notifyListeners();
  }
}

// el proveedor: lleva el registro (log), y reconstruye a sus lectores cuando
// el registro notifica un cambio
class LogProvider extends InheritedNotifier<Log> {
  const LogProvider({super.key, required Log log, required super.child}) : super(notifier: log);

  // la lectura: el proveedor MÁS CERCANO por encima de context
  static Log of(BuildContext context) {
    final provider = context.dependOnInheritedWidgetOfExactType<LogProvider>();
    if (provider == null) {
      throw FlutterError('LogProvider.of: no LogProvider above this widget');
    }
    return provider.notifier!;
  }
}

import 'dart:async';

import 'package:flutter/material.dart';

class ClockProvider extends StatefulWidget {
  final Duration period;
  final Widget child;

  const ClockProvider({super.key, this.period = const Duration(seconds: 1), required this.child});

  // el valor por defecto: una fecha congelada, leída por un widget sin proveedor
  static DateTime of(BuildContext context) =>
      context.dependOnInheritedWidgetOfExactType<_InheritedClock>()?.now ?? DateTime(2026);

  @override
  State<ClockProvider> createState() => _ClockProviderState();
}

class _ClockProviderState extends State<ClockProvider> {
  DateTime _now = DateTime.now();
  Timer? _timer;

  void _start() {
    _timer?.cancel();
    _timer = Timer.periodic(widget.period, (_) => setState(() => _now = DateTime.now()));
  }

  @override
  void initState() {
    super.initState();
    _start();
  }

  // si el padre cambia el período, el temporizador se reinicia
  @override
  void didUpdateWidget(ClockProvider oldWidget) {
    super.didUpdateWidget(oldWidget);
    if (oldWidget.period != widget.period) _start();
  }

  @override
  void dispose() {
    _timer?.cancel();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) => _InheritedClock(now: _now, child: widget.child);
}

class _InheritedClock extends InheritedWidget {
  final DateTime now;

  const _InheritedClock({required this.now, required super.child});

  // se llama cuando el proveedor se reconstruye: ¿deben reconstruirse los
  // lectores? Sí, si la hora ha cambiado
  @override
  bool updateShouldNotify(_InheritedClock oldWidget) => oldWidget.now != now;
}

import 'package:flutter/material.dart';

class Highlighter extends StatefulWidget {
  final Color color;
  final Widget child;

  const Highlighter({super.key, this.color = const Color(0xFFFFF3CD), required this.child});

  @override
  State<Highlighter> createState() => _HighlighterState();

class _HighlighterState extends State<Highlighter> {
  bool _touched = false;
  bool _hovered = false;

  @override
  Widget build(BuildContext context) {
    // MouseRegion: los movimientos del mouse; Listener: los contactos
    // del dedo (o los clics), al nivel más bajo
    return MouseRegion(
      onEnter: (_) => setState(() => _hovered = true),
      onExit: (_) => setState(() => _hovered = false),
      child: Listener(
        onPointerDown: (_) => setState(() => _touched = true),
        onPointerUp: (_) => setState(() => _touched = false),
        onPointerCancel: (_) => setState(() => _touched = false),
        // AnimatedContainer: un cambio de color ANIMADO (200 ms)
        child: AnimatedContainer(
          duration: const Duration(milliseconds: 200),
          color: _touched || _hovered ? widget.color : Colors.transparent,
          child: widget.child,
        ),
      ),
    );
  }
}

// lib/ex15_behaviors/long_press.dart - un botón de pulsación larga
// -------------------------------------------------------------------------
//     LongPressButton(duration: Duration(seconds: 1), onAction: remove, child: ...)
// La acción solo se ejecuta si el botón se mantiene presionado durante
// toda la duración: una protección contra pulsaciones accidentales. Un anillo
// se llena durante la pulsación.
// El llenado es una ANIMACIÓN: un AnimationController produce un
// valor que va de 0 a 1 durante la duración indicada, en cada fotograma de
// la pantalla. Necesita un "ticker" (el latido de los fotogramas): el mixin
// SingleTickerProviderStateMixin lo agrega al objeto State. Un MIXIN es
// la forma que tiene Dart de reutilizar código en varias clases (ver
// autofocus.dart).
// =========================================================================

import 'package:flutter/material.dart';

class LongPressButton extends StatefulWidget {
  final Duration duration;
  final VoidCallback onAction;
  final Widget child;

  const LongPressButton({
    super.key,
    this.duration = const Duration(seconds: 1),
    required this.onAction,
    required this.child,
  });

  @override
  State<LongPressButton> createState() => _LongPressButtonState();
}

// "with": el objeto State recibe, además, el código del mixin
class _LongPressButtonState extends State<LongPressButton> with SingleTickerProviderStateMixin {
  late final AnimationController _animation;

  @override
  void initState() {
    super.initState();
    // vsync: this: el ticker proporcionado por el mixin
    _animation = AnimationController(vsync: this, duration: widget.duration)
      // el fin de la animación: la pulsación duró lo suficiente
      ..addStatusListener((status) {
        if (status == AnimationStatus.completed) {
          _animation.reset();
          widget.onAction();
        }
      });
  }

  // cuando se elimina el widget: sin animaciones huérfanas
  @override
  void dispose() {
    _animation.dispose();
    super.dispose();
  }

  void _start() => _animation.forward(from: 0);

  // el dedo se levanta demasiado pronto: el anillo se vacía
  void _stop() {
    if (_animation.isAnimating) _animation.reverse();
  }

  @override
  Widget build(BuildContext context) {
    return GestureDetector(
      onTapDown: (_) => _start(),
      onTapUp: (_) => _stop(),
      onTapCancel: _stop,
      // AnimatedBuilder: reconstruye SOLO esta parte, en cada fotograma
      child: AnimatedBuilder(
        animation: _animation,
        builder: (context, child) => Row(
          mainAxisSize: MainAxisSize.min,
          children: [
            SizedBox(
              width: 22,
              height: 22,
              child: CircularProgressIndicator(value: _animation.value, strokeWidth: 3, color: Colors.red),
            ),
            const SizedBox(width: 8),
            child!, // el hijo, construido una sola vez
          ],
        ),
        child: widget.child,
      ),
    );
  }
}

Este mixin proporciona un “ticker” (la frecuencia de actualización de la pantalla, 60 cuadros por segundo o más), que toda animación requiere;

[..addStatusListener(...)]: cuando la animación llega al final ([completed]), la pulsación ha durado lo suficiente: la animación se restablece a cero y se ejecuta la acción;
    • líneas 59–63: el dedo toca el botón: la animación parte de 0; si lo levanta demasiado pronto, la animación retrocede;

// -------------------------------------------------------------------------
// La segunda forma de reutilizar un comportamiento: un mixin sobre State.
//     class _MyPageState extends State<MyPage> with FocusOnStart { ... }
// El objeto State recibe un FocusNode (startFocus), que toma el foco
// en cuanto se muestra la pantalla, y que se libera con ella: el mixin
// completa el initState y el dispose de la clase que lo usa.
// "on State<T>": este mixin solo se aplica a un objeto State, cuyos
// métodos puede por tanto usar (initState, dispose, mounted...).
// (Para un campo simple, el parámetro autofocus: true de TextField hace
// lo mismo: el mixin muestra el mecanismo, reutilizable para otra cosa.)
// =========================================================================

import 'package:flutter/widgets.dart';

mixin FocusOnStart<T extends StatefulWidget> on State<T> {
  final startFocus = FocusNode();

  @override
  void initState() {
    super.initState(); // el initState de la clase (o del mixin) "superior"
    // tras la primera visualización: el campo existe, se le da el foco
    WidgetsBinding.instance.addPostFrameCallback((_) {
      if (mounted) startFocus.requestFocus();
    });
  }

  @override
  void dispose() {
    startFocus.dispose();
    super.dispose();
  }
}

// Flutter proporciona todo lo necesario: showDialog() muestra un diálogo
// MODAL sobre la pantalla, y devuelve un Future, resuelto con el valor
// que el diálogo pasa al cerrarse: Navigator.pop(context, value).

//
//     if (await confirm(context, 'Delete this doctor?')) { ... }
//
// Cerrar el diálogo SIN responder (toque fuera, botón Atrás del
// teléfono, tecla Esc) resuelve el Future con null: se trata
// como un "no".
// =========================================================================

import 'package:flutter/material.dart';

Future<bool> confirm(BuildContext context, String message) async {
  final answer = await showDialog<bool>(
    context: context,
    // AlertDialog: un diálogo Material, con un título, un contenido y botones
    builder: (context) => AlertDialog(
      title: const Text('Confirmation'),
      content: Text(message),
      actions: [
        // autofocus: el botón "No" (la opción menos peligrosa) tiene el foco
        TextButton(autofocus: true, onPressed: () => Navigator.pop(context, false), child: const Text('No, go back')),
        FilledButton(
          style: FilledButton.styleFrom(backgroundColor: Colors.red),
          onPressed: () => Navigator.pop(context, true),
          child: const Text('Yes, confirm'),
        ),
      ],
    ),
  );
  return answer ?? false; // null: diálogo cerrado sin respuesta
}

    • líneas 19–22: [showDialog] abre la ventana creada por [builder] y devuelve un [Future<bool?>]: el valor transmitido cuando se cierra la ventana;
    • líneas 23–25: [AlertDialog] es el cuadro de diálogo de [Material Design]: un título, contenido y botones;
    • línea 27: [Navigator.pop(context, false)] cierra la ventana transmitiendo [false]. [autofocus]: el botón “No” (la opción menos riesgosa) tiene el foco (presionar Enter por accidente no elimina nada);
    • línea 36: cerrar la ventana SIN responder (tocar fuera de la ventana, presionar el botón Atrás del teléfono o presionar la tecla Esc) resuelve el [Future] con [null]: se trata como un “no”.

import 'package:flutter/material.dart';

import 'confirmation.dart';

typedef Contact = ({int id, String name});

void main() {
  runApp(
    MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.indigo),
      home: const ContactsPage(),
    ),
  );
}

class ContactsPage extends StatefulWidget {
  const ContactsPage({super.key});

  @override
  State<ContactsPage> createState() => _ContactsPageState();
}

class _ContactsPageState extends State<ContactsPage> {
  final List<Contact> _contacts = [
    (id: 1, name: 'Jean MARTIN'),
    (id: 2, name: 'Alice DURAND'),
    (id: 3, name: 'Luc GERMAN'),
  ];
  String _message = '';

  // una función async: "espera" la respuesta del usuario
  Future<void> _remove(Contact c) async {
    final yes = await confirm(context, 'Delete the contact ${c.name}?');
    // después de un await, la pantalla puede haber desaparecido: comprobamos que sigue ahí
    if (!mounted) return;
    if (!yes) {
      setState(() => _message = 'Deletion abandoned.');
      return;
    }
    final position = _contacts.indexOf(c);
    setState(() {
      _contacts.remove(c);
      _message = '${c.name} has been deleted.';
    });
    // ScaffoldMessenger: muestra un mensaje efímero en la parte inferior de la pantalla
    ScaffoldMessenger.of(context).showSnackBar(
      SnackBar(
        content: Text('${c.name} deleted'),
        action: SnackBarAction(
          label: 'Undo',
          onPressed: () => setState(() {
            _contacts.insert(position, c);
            _message = '${c.name} is back.';
          }),
        ),
      ),
    );
  }

  Future<void> _removeAll() async {
    final yes = await confirm(context, 'Delete the ${_contacts.length} contacts?');
    if (yes && mounted) {
      setState(() {
        _contacts.clear();
        _message = 'All the contacts have been deleted.';
      });
    }
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Example 16 - a confirmation dialog')),
      body: ListView(
        padding: const EdgeInsets.all(16),
        children: [
          for (final c in _contacts)
            ListTile(
              leading: const Icon(Icons.person),
              title: Text(c.name),
              trailing: IconButton(
                icon: const Icon(Icons.delete_outline, color: Colors.red),
                onPressed: () => _remove(c),
              ),
            ),
          if (_contacts.isEmpty)
            const ListTile(
              title: Text('No contact.', style: TextStyle(color: Colors.grey)),
            ),
          const SizedBox(height: 12),
          Align(
            alignment: Alignment.centerLeft,
            child: FilledButton(
              style: FilledButton.styleFrom(backgroundColor: Colors.red),
              // null: botón deshabilitado cuando la lista está vacía
              onPressed: _contacts.isEmpty ? null : _removeAll,
              child: const Text('Delete all'),
            ),
          ),
          const SizedBox(height: 12),
          if (_message.isNotEmpty) Text(_message, style: const TextStyle(color: Colors.indigo)),
        ],
      ),
    );
  }
}
